KORA / BRAIN SYSTEM · 15.08.2026

To nie jest jeden model. To cały system Kory.

Kora łączy lokalne modele językowe, rozpoznawanie mowy PL/EN, pamięć, nastrój, kamery, Hailo, LiDAR, sensory, własny routing komend i warstwę charakteru. Ta strona pokazuje, co już zbudowałem — od słowa „Kora” aż po reakcję robota.

Nie pokazuję tu listy bibliotek. Pokazuję funkcje, które realnie składają się na zachowanie robota.

Voice

Wake-word + XVF3800

Kora używa macierzy mikrofonowej reSpeaker XVF3800. Dedykowany kanał ASR trafia do Vosk, który czeka na wake-word „Kora”, a później otwiera okno na właściwą komendę.

Local models

Modele uruchamiane lokalnie

Rozmowa i analiza obrazu mogą działać na lokalnych modelach uruchamianych przez Ollama. Dzięki temu routing, pamięć i sensory mogą dostarczać modelowi aktualny kontekst robota.

Stan i charakter

Kora ma stan obejmujący m.in. humor, pobudzenie, ciekawość i sarkazm. Nastrój może wpływać na sposób odpowiedzi i ton głosu, ale nie powinien zmieniać technicznego rozpoznania intencji.

Percepcja

Kora nie tylko słucha

Mózg dostaje dane z kamer i sensorów, więc odpowiedź może odnosić się do tego, co robot rzeczywiście widzi lub mierzy.

Vision

Dwie kamery IMX708

Kamera dzienna i szerokokątna NoIR dają dwa różne obrazy świata. NoIR może pracować z podświetleniem IR, a warstwa wizyjna potrafi robić zdjęcia i przekazywać scenę do analizy.

Hailo

Akceleracja widzenia

Hailo jest używane do lokalnej detekcji i śledzenia. Dzięki temu część percepcji może działać niezależnie od dużego modelu językowego.

RPLidar dostarcza chmurę punktów i odległości wokół robota. Dane są używane do mapy, kierunków i oceny najbliższych przeszkód.

Proste kody

Jak wygląda logika bez 7000 linii

To są celowo uproszczone przykłady pokazujące ideę. Produkcyjny kod Kory ma więcej zabezpieczeń, logowania, testów i obsługi błędów.

1. Wake-word: słuchaj tylko „Kora”
from vosk import KaldiRecognizer

WAKE_WORDS = ["kora"]

wake = KaldiRecognizer(model_pl, 16000)
wake.SetGrammar(json.dumps(WAKE_WORDS))
wake.SetWords(False)

if wake.AcceptWaveform(audio):
    text = json.loads(wake.Result())["text"]
    if text == "kora":
        open_command_window()
Idea: osobny, bardzo mały recognizer do wybudzenia. Właściwe zdanie jest dekodowane dopiero później.
2. Dwa języki — wybierz lepsze rozpoznanie
pl_text, pl_conf = decode_pl(audio)
en_text, en_conf = decode_en(audio)

if current_language == "en":
    command = en_text
else:
    command = pl_text

handle_command(command)
W prawdziwej wersji jest więcej reguł: confidence, aliasy ASR, wake-prefix, tryb TFT i fallback.
3. Całe zdanie zamiast jednego słowa
from difflib import SequenceMatcher

def similarity(spoken, target):
    return SequenceMatcher(
        None,
        spoken.lower(),
        target.lower()
    ).ratio()

spoken = "what du u think abaut new battery"
target = "what do you think about the new battery"

if similarity(spoken, target) > 0.70:
    intent = "new_battery"
Produkcja idzie dalej: porównuje też słowa niosące znaczenie i blokuje podobne gramatycznie zdania o innym temacie.
4. Nastrój wpływa na odpowiedź
state = {
    "humor": 92,
    "curiosity": 96,
    "sarcasm": 100
}

if state["sarcasm"] > 80:
    reply = sarcastic_reply(intent)
else:
    reply = normal_reply(intent)
Kluczowa zasada: nastrój zmienia charakter odpowiedzi, nie to, czy Kora rozpoznała intencję.
5. Explore: kilka sensorów, jedna decyzja
neck.move(pan=90, tilt=0)

distance = vl53.read_cm()
points = lidar.scan(seconds=4)
photos = cameras.capture()

scene = analyse(
    distance=distance,
    lidar=points,
    photos=photos
)

voice.say(comment(scene))
W realnym Explore dochodzą timeouty, dead-zone, kolejność aktywacji, ochrona ruchu i logowanie.
6. Pamięć zdarzenia
event = {
    "type": "observation",
    "source": "camera",
    "text": "Marcin is working at the bench"
}

memory.save(event)

recent = memory.recent(limit=5)
answer = model.ask(question, context=recent)
Idea: model nie musi dostawać całego życia Kory — tylko kontekst potrzebny w danym momencie.

Kontekst

Nie każde pytanie do dużego modelu

Godzina, data, prosta komenda czy znana reakcja powinny mieć szybki lokalny handler. Duży model zostaje dla pytań, które naprawdę wymagają generowania odpowiedzi.

Głos

TTS z tonem i stanem

Piper generuje głos, a dodatkowa warstwa może zmieniać tempo i ton zależnie od typu wypowiedzi i aktualnego stanu Kory.

2026

Raspberry Pi 5, Hailo, dwie kamery, LiDAR, PL/EN, lokalne modele, pamięć, Mood Panel, Explore i rozbudowana warstwa osobowości.

Teraz

Aluminiowa konstrukcja, nowe zasilanie i praca nad tym, żeby rozmowa była bardziej naturalna, odporna na błędy STT i nadal przewidywalna technicznie.

Najważniejsza zasada: bezpieczeństwo ma pierwszeństwo

STOP, release, PWM-off i mechanizmy awaryjne muszą omijać humor, sarkazm i ciężkie modele. Charakter Kory nigdy nie powinien przejmować ścieżki bezpieczeństwa.

Jak oznaczam status

WORKING oznacza funkcję sprawdzoną w realnym systemie. IN TESTING oznacza działający kod, który czeka na pełny test głosowy lub regresyjny. IN PROGRESS oznacza moduł działający częściowo i nadal rozwijany.
